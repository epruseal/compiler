# 시행일 예외와 조사 기록

이 문서는 시행일 기준 이력을 설계할 때 발견한 사례와 사용자 결정을 함께 유지한다. 작업 설계의 정본과 결정 원문은 [compiler 이슈 1](https://github.com/epruseal/compiler/issues/1)이다. 측정 정정과 재현 스크립트는 [측정 정정 댓글](https://github.com/epruseal/compiler/issues/1#issuecomment-6407194022), 중복과 오류 사례는 [중복 조사 댓글](https://github.com/epruseal/compiler/issues/1#issuecomment-6410023657)에 있다. 이 문서는 예외 사실과 사례의 정본이다.

## 상태와 판정

2026-11-11 중간 게시다. r22 구현과 독립 검증이 진행 중이며, "(예측)" 표시 값은 r22 실측 뒤 바뀔 수 있다.

다음 문단은 2026-10-27 기준의 낡은 상태 기록이며 이력으로 남긴다. 2026-10-27 기준 시행일 모드는 구현하지 않았고 실제 이력 생성과 독립 실행 검증도 하지 않았다. 아래 선택은 처리 기준이지 문제 해결의 증거가 아니다. 모든 사례는 미해결이다. 해결로 바꾸려면 해당 기준의 사용자 승인을 확인하고 구현한 뒤, 실제 XML과 생성된 Git 이력의 순서, 날짜, tree 및 기존 공포일 모드의 비회귀를 독립 검증해야 한다. 기준이 미승인인 사례는 승인 전까지 미해결이다.

시행일 이력은 완전한 판본 스냅샷을 선택된 단일 날짜 순서로 재생한다. 조문별 효력이나 각 시점의 법적 유효 법문을 보장하지 않는다. 미래 시행 판본도 포함하므로 HEAD를 오늘의 유효 법문으로 해석하지 않는다. 판례는 범위 밖이다. 아래 실물 사례는 자치법규와 행정규칙이며, 직접 확인한 법령 사례는 없다.

## 사용자 결정과 미승인 경계

- 시행일 `99991231`은 미정 값이다. 부칙을 해석한다. 그대로 미래 날짜로 정렬하면 판본이 이력 끝에 놓인다.
- 시행 문구가 없고 적용 대상인 조례와 규칙은 공포일 다음 날부터 20일을 세어 공포일에 21일을 더한다. 교육규칙은 원천이 교육규칙으로 명시한 판본만 적용한다. 이를 판별할 원천 필드는 미승인이다. 고시와 공고는 사용자가 같은 방식의 5일 계산을 선택했다. 리드는 이를 고시일 또는 공고일에 6일을 더하는 계산으로 읽었다. 6일째와 7일째 중 효력 발생일을 정한 공식 출처는 확인하지 못했다. 두 기간 모두 휴일 때문에 미루지 않는다. 법적 근거와 적용 대상은 이슈 본문의 결정 기록을 따른다.
- 빈 부칙에서도 본문에 시행 문구가 있으면 본문을 우선한다. 제개정 필드도 참조한다. 부칙이 있으나 시행 문구를 찾지 못한 경우를 빈 부칙과 같다고 단정하지 않는다. XML 전체 내용이 비어 있으면 원천 누락 가능성을 배제하지 못한다.
- 공포일보다 이른 명시 시행일은 원문 날짜를 사용한다. 이 결정은 소급 효력의 적법성을 보장하지 않는다.
- 부칙과 시행 문구가 없는 도달주의 판본은 발령일을 도달일로 추정한다. 자치법규 훈령과 예규는 공포일자를 쓴다. 법원 예규뿐 아니라 중앙행정기관과 자치법규의 해당 판본에도 적용한다. 의회규칙은 제외한다. 추정 판본 목록을 남기고 시행일 모드의 메시지와 frontmatter에만 추정을 표시한다. 표시 형식은 미승인이다. 발령일 자체는 실제 도달의 증거가 아니다.
- 시행일이 깨졌더라도 부칙에서 추출할 수 있으면 그 날짜를 사용한다. 추출하지 못하면 미해결이다. 공포일 또는 발령일이 깨진 경우 일련번호를 보조 정렬에 사용한다. 유효한 날짜와 깨진 날짜가 같은 시행일 묶음에 섞일 때의 정렬은 미정이다.
- 자치법규 연혁 중복은 표기와 메타데이터만 다른 경우 합친다. 요소가 한쪽에만 있어도 그 요소의 내용이 공백뿐이면 사용자는 없는 요소와 동등한 공백 차이로 보기로 했다. 글자가 있으면 내용 차이로 보고 미해결에 둔다. 별도로 존재하는 조제목, 날짜 또는 내용 차이는 이 결정으로 없어지지 않는다.
- 전체 부칙 해석 규칙, 승인된 1개월 계산 외의 월과 연 단위 기간 계산, 단서 처리, 미해결 판본이 있는 빌드의 처리와 추정 표시 형식은 미승인이다. 시행일 오류에 기본 규칙과 도달 추정을 적용할지도 별도 승인 전이다. 결정된 일부 선택을 전체 문법의 승인으로 확대하지 않는다.

## 사례

각 MST는 해당 XML의 `자치법규일련번호` 또는 `행정규칙일련번호`에서 직접 확인했다. 날짜는 원본 메타데이터다. 원문 인용은 XML 텍스트를 보존한다. 인용의 가운뎃점은 원문의 U+00B7이며 직접 작성한 문장에는 사용하지 않는다. 사례의 파일 위치와 재조회 방법은 아래 재현 절에 있다. 개별 사례의 적용 건수는 미확정이며 날짜별 관측 표를 참고한다.

### E-LABEL: 부칙 귀속과 인식 실패

자치법규 MST `1006223`, 보성군 수리계 조직 및 운영에 관한 조례는 공포일 `20020821`, 시행일 `99991231`이다. 유일한 부칙은 “부     칙 (2002. 8. 1.) 제1조(시행일) 이 조례는 공포한 날부터 시행한다.”로 시작한다. 라벨 날짜와 공포일이 다르지만 시행 문장은 공포일을 기준으로 명시한다. 2026-10-27 사용자 정정에 따라 이 사례의 시행일은 공포일인 `2002-08-21`이다. 이 사례에 20일 원칙을 적용한다는 이전 설명은 철회한다.

부칙 표제 날짜의 불일치만으로 명시된 시행 문장을 배제하거나 기본 20일 원칙을 적용하지 않는다. 다른 불일치 사례의 부칙 귀속과 처리 기준도 원문별로 재검토한다.

2026-11-03 사용자 결정은 단일 부칙의 라벨 날짜 불일치를 다음과 같이 정한다. 질문 도구 응답 원문은 "부칙라벨 등 직접 쓰여있는 일자가 공포일보다 우선함."과 "라벨 일자 우선, 단 공포일 이전이면 공포일"이다. 자치법규 판본의 유일한 부칙이 "공포한 날부터 시행"만 정하고 그 부칙 라벨 날짜가 판본의 공포일과 다르면, 시행일은 라벨 날짜와 공포일 중 늦은 날이다. 이 결정은 2026-10-26의 "20일 원칙 적용" 선택을 대체한다. MST `1006223`은 라벨 `2002. 8. 1.`이 공포일보다 이르므로 공포일 `2002-08-21`을 유지한다. MST `847263`은 `2006-06-28`, MST `806099`는 `2008-03-21`이 된다. 누적 부칙에서 자기 라벨을 찾지 못한 경우, 라벨 날짜와 번호가 서로 모순인 경우, 상대기간과 조건과 단서가 있는 시행 문장은 미해결로 둔다. 행정규칙과 법령에는 이 결정을 적용하지 않는다. 라벨의 날짜와 번호가 모두 판본과 다르면 다른 개정의 부칙으로 보고 미해결로 둔다(2026-11-03 사용자 결정 user-label-both-differ-unresolved-20261103). 이 결정은 "둘 다 다르면 늦은 날"을 쓰던 이전 리드 판정을 대체한다. 라벨에 번호만 있고 그 번호가 판본과 다르면 직접 쓰인 날짜가 없으므로 미해결로 둔다. 이 처리는 사용자 결정이 아니라 리드의 보수적 기본값이다. 리드의 보수적 기본값에 따라 타법개정과 일괄개정 판본에는 이 결정과 위의 귀속 공포일 결정을 적용하지 않고 미해결로 둔다. 이 범위는 사용자 판단이 필요한 열린 항목이다. 라벨 날짜에는 상한을 두지 않으며, 라벨 날짜를 적용한 판본은 생성기가 진단 목록으로 따로 남긴다.

2026-11-03 17:48 KST 사용자는 질문 도구에서 네 가지를 결정했다. 첫째, 폐지제정 판본은 "제정으로 처리"한다. 기존 조례를 폐지하고 같은 이름으로 새로 제정한 판본으로 보며, 새 법문은 시행일부터 현행이고 부칙 규칙도 제정과 같이 적용한다. 둘째, 별도 조문의 부분 시행 문장이 있으면 "일반 시행일 사용"이다. 일반 시행 문장의 날짜를 판본 시행일로 쓰고 별도 조문의 시기는 근거에만 둔다. 단서("다만", "단,")가 붙은 문장은 미해결이다. 셋째, 라벨 날짜가 같은 법규의 다음 판본 공포일보다 늦으면 "다음 판본보다 늦으면 미해결"이다. 넷째, 부칙 해석 규칙 전체를 "이대로 승인"했다. 그래서 위에서 리드의 보수적 기본값으로 적은 규칙(타법개정, 일괄개정, 타법폐지 제외, 번호만 불일치, 날짜와 번호 모순, 단서, 라벨 날짜 상한 없음과 진단 목록)은 이제 사용자 결정이다. 폐지제정은 첫째 결정에 따라 제외 대상이 아니다.

2026-11-03 사용자는 부칙 라벨의 두 자리 연도와 '제' 없는 번호도 읽으라고 결정했다. 응답 원문은 "두자리 읽어야 하지만, 2000년대도 있을 수 있음. (ex: 25.01.02는 2025.01.02). 제 없는 번호도 읽어야 함."이다. 세기 선택은 리드 기술 재정이다. 두 자리 연도는 19YY와 20YY 가운데 판본 공포일에 더 가까운 쪽을 고르고, 거리가 같거나 공포일이 깨졌으면 미해결로 둔다. 세기를 고른 뒤에는 위의 라벨 규칙을 그대로 적용한다. 날짜가 둘 들어 있는 라벨(예: "<제정 95. 3. 17, 개정 95. 10. 20>")은 이 결정에 들지 않아 미해결이며 사용자 확인 대상이다.

#### 시행 문구 탐지와 판독 범위 (2026-11-11 r22 수정)

시행 문구가 있으면 21일 기본값을 쓰지 않고, 시행 문구가 없을 때만 21일을 쓴다(이 문서 14~15행의 규칙). 그래서 시행 문구가 있는데 탐지가 놓치면 승인되지 않은 21일이 확정된다. 이 방향은 비보수다. 반대로 시행 문구가 없는데 과하게 잡으면 미해결로 남는다. 이 방향은 보수다.

2026-11-09 사용자는 줄 머리(제N조, 부칙, 원문자, 번호, 목 번호 줄)에서 문장을 자르는 정밀 경계를 골랐다(응답 "정밀 경계 계속 (r17c)", "r17c로 바로 구현, 구현 뒤 검증"). 그 뒤 r18, r19, r20에서 경계 규칙을 고쳤다(응답 "바로 구현, 구현 뒤 검증", "한 줄 수정 + 경계 규칙 전체 대칭 점검, 바로 구현 (Recommended)", 리드 재정 r20-reference-cells-lead-20261110). 회차마다 검증에서 같은 부류의 결함이 다시 나왔다. 줄 머리 경계가 시행 문장을 중간에 끊어 승인되지 않은 21일을 확정하는 결함이다.

2026-11-10 사용자는 "넓게 탐지로 전환"을 골랐다(결정 id user-broad-detection-20261110). 선택지 원문은 다음과 같다. "줄 머리 경계를 없애고 128자 상한과 문장 끝 마침표만 남깁니다. 날짜를 잘못 만드는 경로는 사라집니다. 대신 '제2조 시장은 사업을 시행한다'처럼 다른 조문의 '시행'이 128자 안에 오면 20일 원칙 대신 미해결이 됩니다(공포일부터 조회됨). 이 보수 한계를 사용자 승인으로 적습니다." 이 결정은 위 정밀 경계 결정과 리드 재정을 대체한다. 줄 머리 경계와 그 예외 규칙(참조 연결, 앞 줄 접속어, 번호 줄 날짜 보호)은 없어졌다. 아래 규칙은 이 결정(r21)을 반영한다.

탐지는 "이 조례는", "이 규칙은" 같은 주어 뒤에서 시작한다. 구간은 괄호와 따옴표 밖에 있는 문장 끝 마침표("."과 이데오그래픽 마침표 U+3002)에서 끝난다. 마침표 바로 앞이 종결형 글자(다, 함, 음, 임, 됨)이거나 닫는 괄호, 닫는 따옴표여야 한다. 숫자 뒤 마침표는 날짜의 일부로 보아 문장 끝으로 보지 않는다. 전각 마침표 U+FF0E와 반각 이데오그래픽 마침표 U+FF61은 날짜의 점과 구별하지 못하므로 문장 끝으로 보지 않는다. 그런 마침표가 없으면 구간은 본문 끝까지 간다.

사용자 결정의 선택지는 주어 뒤 128자 상한도 남겼다. r21 구현에서 상한을 없앤 변형과 상한이 있는 안의 표본 상태 차이가 0이었다. 그래서 리드는 상한을 없애 128자 밖의 동사를 놓치는 경로도 닫았다(2026-11-10).

탐지기가 찾은 시행 문장을 날짜 판독기가 읽지 못하면 그 문장을 판독 불가로 표시한다. 줄을 넘는 문장, "시행한다" 밖의 활용형("시행함", "시행하되", "시행된다" 등), 판독기가 모르는 주어가 그 대상이다. 같은 목표 구역의 다른 문장이나 이전 규칙이 고른 다른 부칙 블록의 날짜로 확정하거나 추정하지 못하게 막는다. 이미 미해결인 행은 기존 근거를 유지한다(2026-11-11 r22의 좁은 Guard). 예를 들어 "이 조례는 같은 조" 다음 줄 "(1)에 따른 승인을 받은 날 시행한다."와 "이 조례는 2030년 1월 1일 시행한다."가 한 구역에 있으면 미해결이다.

줄을 넘는 "효력을 발생한다"도 이 대응 검사에 포함한다. 날짜 판독기가 이미 지원하는 "법률" 주어를 탐지기와 대응 검사도 인식한다. 탐지됐지만 판독되지 않은 문장을 누락한 채 다른 날짜를 확정하지 않도록 인식 목록과 판독 범위를 대조한다. 별도 조문의 부분 시행 문장을 일반 시행일과 구분하는 기존 승인 규칙은 바꾸지 않는다.

사용자 승인 보수 한계(user-broad-detection-20261110): 다른 조문이나 항의 시행 동사가 주어 뒤에 오고 그 사이에 문장 끝 마침표가 없으면 시행 문구로 탐지된다. 예를 들어 "이 조례는 운영을 정하며" 다음 줄 "제2조 시장은 사업을 시행한다."는 20일 원칙 대신 미해결이다. 실데이터에서는 MST `1151198`(일부개정, 공포 `2012-03-08`)이 이 한계로 r20의 확정에서 미해결로 바뀌었다. 마지막 부칙의 제2조(적용례) "이 규칙은 2012년 1월 1일 이후 시행되는 임용시험부터 적용한다."의 "시행되는"이 탐지됐기 때문이다(2026-11-10 사용자 결정 user-hadoe-proviso-20261110이 받아들임). 미해결 판본은 공포일부터 후보로 조회되므로 날짜 조회에서 빠지지 않는다. 앞 문장이 종결형 뒤 마침표로 끝나면 구간도 거기서 끝난다. 그래서 "제1조(목적) 이 조례는 운영을 정한다." 다음 줄 "제2조 시장은 사업을 시행한다."는 시행 문구가 없는 본문으로 보아 21일이다.

- 문장 끝 경계: "이 조례는 위원회 구성이 완료됨. 그 다음 날 시행한다."처럼 종결형 뒤 마침표가 구간을 먼저 닫으면 뒤의 주어 없는 시행 문장을 놓칠 수 있다. "이 조례는 '공포한 날'. 시행한다."처럼 닫는 따옴표 뒤 마침표가 있는 형태도 같다. 사용자는 이 형태를 승인 한계로 수락했다. 이 수락은 이미 넣기로 한 어휘의 누락이나 다른 승인 규칙의 회귀를 면제하지 않는다.

#### 한 부칙 제목의 서로 다른 날짜 라벨 (2026-11-09)

결정 B(user-last-section-unlabeled-promulgation-20261104) 셋째 항목은 "한 제목에 서로 다른 날짜 라벨이 둘이면 미해결"이라고 정한다. 구현은 기존 라벨 판독 함수를 그대로 쓴다(리드 재정, 1139512 오탐 수정 때 정한 "날짜나 번호 모양일 때만 라벨 후보"). 이 함수가 읽을 수 있는 라벨로 판정하고 날짜를 읽어 낸 괄호 그룹만 센다. 그렇게 읽은 날짜가 서로 다르면 그 제목 전체를 읽지 못한 라벨로 보고 미해결로 둔다. 라벨 후보가 아닌 괄호는 세지 않는다.

이 판독 함수는 설명 문구 괄호의 날짜도 날짜 라벨로 읽는다. 리드는 이 판독을 그대로 두기로 했다(2026-11-09). 결과가 바뀐다면 방향은 확정에서 미해결이고, 미해결 판본은 공포일부터 후보로 노출되어 날짜 조회에서 빠지지 않는다. 설명 문구를 날짜 라벨에서 뺄지는 사용자 확인 항목이다. 이런 설명 문구 괄호가 제목에 있는 판본의 예:

## 측정 도구의 한계

관측 도구 결함은 법적 예외나 원천 데이터 오류와 구별한다. 시제품은 시행 문구 누락, 라벨 없는 부칙 오분류, 엔티티, 조제목, 중첩 구조와 독립 oracle 오염 때문에 분류를 확정하지 못했다. 예를 들어 `1081693`의 엔티티와 `1079521`의 여러 부칙은 원본에서 직접 확인했다. `931559`는 본문 속 부칙이어서 부칙 필드만 검색하면 놓친다. `638543`의 history 사본은 조제목과 날짜가 달라 중복 비교에 영향을 준다.

2026-10-27 독립 실행의 대상은 부칙 라벨과 소비 범위를 조사하는 관측 코드 및 검사기다. 당시 대상 버전은 등록된 파일 전체의 SHA-256 manifest `b617febe1c4cfff750af4174f110d71a211b16f480fe9ba921237057b8b49e41`로 식별한다. 이 해시는 파일 목록의 식별자이며 코드 자체나 공개 재현 자료를 대신하지 않는다. 당시 실행은 `1079521`과 `1081693`의 MST와 원문을 확인했고 해당 원본 수리 조건은 통과했다. 전체 판정은 FAIL이었다.

그 실행의 합성 입력과 DB 변이에서는 미지원 라벨 조기 절단, proof 위조 검사 누락, merged 소유권, 전체 경로 oracle 배정, 엔티티 사유, metadata 표기 검사와 독립 계약의 미완료가 확인됐다. 이 기록은 당시 버전의 판정이며 이후 버전의 현재 상태를 보증하지 않는다. 원본 사례 대조와 합성 변이 결과를 실제 법규의 종류 수나 법적 미해결 건수로 세지 않는다. 당시 독립 판정은 로컬 검증 자료이며 공개된 코드와 전체 입력은 이 문서에 포함되지 않았다. 따라서 해시만으로 실행을 재현할 수 없다. 새 버전의 적용 규모는 독립 검증으로 따로 확정한다.

2026-10-27 G1 입력 대사 r4의 외부 합성 검사와 실패 주입 대조는 승인 manifest의 중복 JSON 키, JSON pointer 문법, 문서 인용 범위와 완료 manifest 게시 단계에서 결함을 확인했다. 해당 audit 코드의 SHA-256은 `d492414743566003029688778ea6e8f77eae96210d644781510536a11a586268`이며 외부 전체 판정은 FAIL이다. 리드는 네 범주를 수정 설계 대상으로 채택했다. 같은 판의 독립 실행도 FAIL이며, 승인 JSON의 중복 키 허용과 실제 EFBIG 실패 후 0바이트 최종 manifest 잔존을 재현했다. 후속 G1 입력 대사기 수리는 외부 검증과 새 독립 실행 검증에서 PASS를 받았다. 이 PASS는 입력 대사기에 한정하며 전체 관측기의 PASS가 아니다. [G1 검증 기록](https://github.com/epruseal/compiler/issues/1#issuecomment-6466578985)을 참조한다.

독립 재계산은 입력 105개, 인용 근거 194개와 대조군 13개를 확인했고 원본 보존 검사도 PASS였다. 이 수치는 실법령 예외 건수가 아니다.

이 검사는 실제 MST나 실제 원문 모집단을 측정하지 않았으므로 실법령 예외나 원천 오류 건수에 더하지 않는다. 기존 입력 지원과 법적 기준은 바뀌지 않았다. 로컬 판정과 코드 및 입력은 공개 재현 자료가 아니므로 이 해시만으로 실행을 재현할 수 없다.

2026-10-28 사용자는 관측 도구의 측정 결과를 검증한 불변 사본과 해시에 결합해 게시하기로 정했다. 원본의 마지막 확인 이후 변경은 해당 실행의 보장 밖이며 새 측정 대상으로 둔다. 모든 검사와 파일 닫기 뒤 원자 게시와 검증 가능한 manifest를 완료 기준으로 삼는다. 이후 stdout 오류는 통지 실패로 구분하고 완료 결과를 다시 검사해 확인한다. [사용자 재정 기록](https://github.com/epruseal/compiler/issues/1#issuecomment-6460877186)은 이 게시 계약이 법령 해석과 시행일 기준을 바꾸지 않는다고 명시한다.

이 결정은 실제 MST 예외 건수가 아니며 과거 FAIL을 바꾸지 않는다. 후속 G1 입력 대사기 수리는 양 채널 검증을 통과했다.

C1은 최종 audit pointer에서 audit와 change-map의 `new_fields`를 생성하도록 정합성을 수리했고 두 채널 검증을 통과했다. B2는 parse 실패와 DB 재사용 관측기를 r3로 수리하고 observer 불변 증거를 보충했으며 필수 사후 검증을 통과했다. 이 판정들은 해당 수리에 한정한다. 전체 hit, origin, reasons와 date role 등의 후속 검증, 전체 관측기 수리와 시행일 옵션 구현은 미완료다. 입력 계약의 한정 정정과 미검토 범위는 [정정 기록](https://github.com/epruseal/compiler/issues/1#issuecomment-6468049507)을 참조한다.

최근 검사기가 보고한 오류는 검사기 결함과 역할 결속의 미해결 문제를 포함한다. 이를 새 MST 원문 오류로 확정하지 않는다. 이를 MST 오류 건수에 더하지 않는다. 새로 확정된 MST 원문 사례는 없다. 실서버 metadata와 모델 지시 차단 성능은 검증하지 않았다.

2026-10-27 질문 대사 r2는 합성 검사와 과거 시제품 결과의 대사 수리다. 위 실제 원본 사례와 구별하며 실제 MST 예외 건수에 더하지 않는다. 원본 입력을 보존하고 `matched` 전체를 별도로 복원했다. 제공 목록과 전체 및 `explicit_date` 하위집합 사이의 양방향 차집합을 기록했다. 여섯 질문의 기존 membership과 교집합, 합집합은 바뀌지 않았다.

외부 판정과 독립 재계산은 이 대사 수리에 PASS를 줬다. 법령 관측기의 앞선 전체 FAIL은 유지하며 대사 수리의 PASS를 관측기 통과로 해석하지 않는다.

Q2a의 기준일 해석에 실패한 14건은 기존 membership에 남는다. 원문 귀속과 정책 효력은 검증하지 않았다. 판본 교차표도 만들거나 검증하지 않았다. 제개정 구분과 전체 라벨 역시 원시 행만으로 검증되지 않는다. 대사 결과의 SHA-256은 `d2a11142c28a29fe76058cf7ec8455953d1cdbec7be584ef37075b4d51a365ad`다. 로컬 판정과 입력 및 코드가 공개 재현 자료로 제공되지 않았으므로 이 해시만으로 재현할 수 없다.

실패한 대사 CLI는 종료 코드 1을 반환해도 빈 디렉터리, `contract.json`만 있는 디렉터리 또는 잘린 JSON을 남길 수 있다. 디렉터리나 파일의 존재만으로 완료를 판정하지 않는다. 종료 상태와 결과 파일의 완전성 및 내용을 검사한다.

## 안전한 원문 재현

캐시 루트를 `CACHE`에 지정한다. 파일을 읽기만 하며 선택한 MST만 조회한다. 같은 MST가 원 사본과 history에 모두 있는 경우 두 경로를 각각 확인한다. XML 내부 일련번호가 요청한 MST와 같아야 한다. 파일명만으로 식별자를 추정하지 않는다. 공백과 엔티티의 원래 표기는 XML 원문에서도 확인한다.

```sh
CACHE=/path/to/.cache
KIND=ordinance
MST=638543
python3 -I - "$CACHE" "$KIND" "$MST" <<'PY'
import pathlib
import sys
import xml.etree.ElementTree as ET

root, kind, mst = pathlib.Path(sys.argv[1]), sys.argv[2], sys.argv[3]
if kind not in ('ordinance', 'admrule') or not mst.isdecimal():
    raise SystemExit('invalid kind or MST')
serial_tag = '자치법규일련번호' if kind == 'ordinance' else '행정규칙일련번호'
folders = [root / kind]
if kind == 'ordinance':
    folders.append(root / kind / 'history')
for folder in folders:
    path = folder / (mst + '.xml')
    if not path.is_file():
        continue
    tree = ET.parse(path)
    serial = tree.findtext('.//' + serial_tag)
    if serial != mst:
        raise SystemExit(f'MST mismatch: {path}: {serial!r}')
    print(f'\n{path} {serial_tag}={serial!r}')
    for element in tree.iter():
        if element.tag in ('자치법규명', '행정규칙명', '시행일자', '공포일자',
                           '발령일자', '부칙내용', '조내용', '조문내용', '제개정문',
                           '제개정이유', '제개정이유내용'):
            print(element.tag, repr(''.join(element.itertext())))
PY
```

원시 XML을 직접 보려면 `cat "$CACHE/$KIND/$MST.xml"`을 사용한다. history는 `"$CACHE/ordinance/history/$MST.xml"`을 지정한다. 법령 사례를 새로 추가할 때는 목록 메타데이터의 법령일련번호와 상세 XML identity의 대응을 확인한다. 파일명만으로 MST를 추정하지 않는다. 전수 측정은 이슈에 게시된 당시 스크립트, 입력 범위, 도구 버전과 입력 해시를 확보한 뒤 별도로 실행한다. 당시 스크립트가 디렉터리 순서에 의존한 표본은 다른 캐시에서 같은 표본을 보장하지 않는다.

## 갱신 양식

새 사례와 결정은 이 문서에 추가한다. 원문을 직접 대조하고 MST를 반드시 기록한다. 근거와 상태를 함께 갱신한다. 빈 건수나 미확정 건수를 0으로 바꾸지 않는다.

분류: 법적 예외 / 원천 데이터 오류 / 관측 도구 결함
발생 조건과 이력 영향:
원천 종류와 XML MST:
법규명, 시행일, 공포일 또는 발령일:

관측일, 모집단, 중복 처리, 측정 도구와 입력 해시:
관측 건수와 출처: 원문 관측 / 정책 적용 미확정 / 무효 시제품
